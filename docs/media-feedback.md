# 素材プレビューからの修正指示

画像・動画への指示は通常のプロンプトと分離したセッション単位の下書きとして扱う。
画像は素材ごとに自由記述1件、動画は全体コメントまたは再生位置付きの複数コメント。
入力は自動保存し、プレビューを閉じても保持する。「完了」は送信ではない。
実際の送信はチャット入力欄から行い、プロンプトが空でも指示だけで送れる。

## 状態と対象の識別

`DraftService.mediaFeedback` が `MediaFeedbackCubit` を所有し、SharedPreferencesへ保存する。
ルートを開く前にセッションへのbindingを捕捉し、別セッションへ切り替えても指示の所属を変えない。
pendingセッションから実IDへの移行では、開いたままのプレビューも同じ移行先を使う。

- ファイル: プロジェクトパス＋ファイルパス。
- Imagegen: ツール結果に含まれる生成画像ID。
- 通常のツール結果/過去の添付画像: 画像ID。
- 未送信の添付画像: 内容のSHA-256。

動画の時刻は「この時刻にコメント」を押した瞬間に固定して一時停止する。
内部ではミリ秒を保持し、表示と送信時は分・秒にする。入力中も保存する。
コメントの時刻からシークでき、本文から編集できる。時刻を外すと全体コメントになる。

## 送信と互換性

既存の`sendMessage`に渡す直前に、素材ごとに指示をまとめて末尾へ追記する。
動画のコメントは時刻順。通常のプロンプト編集欄の内容は書き換えない。
Bridgeの新しいメッセージ型やプロトコル変更はない。Claude/Codex共通の既存送信経路を使う。

ファイルパスがある素材はパス（通常ファイルではプロジェクトパスも）を明記する。
保存パスのない画像は既存の画像添付として送信し、指示に添付番号を記載する。
既存添付と内容が同じ場合は重複させない。画像の取得失敗・合計5枚超過では送信せず下書きを残す。
送信経路が受け付けた時点で送信したスナップショットと一致する指示だけを削除する。
送信中の追記・変更は削除しない。以後の配信再試行は既存送信キューの責務とする。

## 素材更新と制約

ファイル一覧から取得済みの更新時刻が変わった場合は送信を止め、プレビューで
「更新後の素材に適用」を押すまで既存コメントを新しい内容へ適用しない。
これは既存の更新時刻キャッシュに基づく検出であり、未取得時やキャッシュが古い場合まで
内容の同一性を保証するものではない。動画フレームの添付・時間範囲指定・画像上のピン留めは対象外。
