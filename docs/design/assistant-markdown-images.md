# アシスタント本文の画像表示

アシスタントが本文に Markdown の画像記法 `![ラベル](パス)` で書いたローカル画像を、
メッセージの下にサムネイルのギャラリーとして表示する。

## 目的

Codex 内蔵の画像生成は `ImageGeneration` のツール結果として届き、専用のギャラリーで
表示される。一方 Claude がスクリプト経由で生成した画像や、選択を求める候補画像は、
本文にパスが書かれてもタップして 1 枚ずつ開くしかなかった。

## 何を表示対象にするか

「どのツールが作ったか」ではなく「エージェントが見せると明示したか」で判定する。

- 対象: 本文の `![ラベル](パス)`（絶対パス、プロジェクト相対パス、`file://`）
- 対象外: 通常のリンク `[名前](パス)`、ツール結果に含まれるパス、`http(s)` や `data:` の画像、
  コードブロック・インラインコード内の記法

動作検証のスクリーンショットなどは、エージェントが画像記法で書かない限りチャットに並ばない。
ツール結果の画像は従来どおりツール結果側に付く。

## Bridge

- `markdown-images.ts` が本文から画像記法を抽出し、`ImageStore` に登録する。
- 読める範囲はファイルプレビューと同じ（`BRIDGE_ALLOWED_DIRS` と `BRIDGE_READONLY_DIRS`）。
  字句上のパスと symlink 解決後の実パスの両方を確認し、範囲外・存在しないファイルは添付しない。
- 1 メッセージあたり最大 12 枚。サイズ上限と対応形式は `ImageStore` に従う。
- 添付する経路:
  - ライブ: `SessionManager` が `assistant` メッセージを配信する前に付ける（Claude・Codex 共通）。
  - 履歴復元: Claude の過去履歴（`preparePastHistoryMessages`）と Codex の履歴変換で付け直す。
    `ImageStore` はメモリ上にあるため、Bridge 再起動後も復元時に再登録される。

## プロトコル

`assistant` メッセージと、過去履歴の `role: "assistant"` に任意の `images` を追加する。

```ts
images?: Array<{
  id: string;
  url: string;          // /images/<id>
  thumbnailUrl?: string;
  mimeType: string;
  path: string;         // Bridge ホスト上の絶対パス
  alt?: string;         // 画像記法のラベル
}>;
```

新しいクライアントメッセージは追加していない。

## 互換性

- 新しい Bridge と古いアプリ: 未知の `images` は無視され、従来どおりの表示になる。
- 古い Bridge と新しいアプリ: `images` が届かないのでギャラリーは出ない。本文の画像記法は
  タップでファイルプレビューを開くラベルとして表示される。

## アプリ

- 本文中のローカル画像記法は、アイコンつきのラベルとして描画する（タップでファイルプレビュー）。
  端末から Bridge ホストのパスを直接読むことはできないため、画像そのものは本文中に埋め込まない。
- 添付された画像は `GeneratedImageChatGroup` でメッセージの下に並べる。サムネイルにはラベル
  （未指定ならファイル名）を重ね、候補を見分けられるようにする。
- プレビュー画面では見出しにファイル名、本文にラベルを出す。画像へのフィードバックには
  `path` が保存先として渡る。
